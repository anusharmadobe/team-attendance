# Team Attendance — AEM Forms India PM & Content

Tracks daily office / WFH / Sick / Leave status for the AEM Forms India PM & Content team, parsed from Slack channel **#aemforms-india-pm-chl-design** (`C043FKMNUNM`).

**Live dashboard →** https://anusharmadobe.github.io/team-attendance/

---

## What this system does

1. Reads attendance status messages from a Slack channel (manual posts by team members)
2. Classifies each message into `office / wfh / sick / leave / no_info`
3. Stores structured daily records per person in `data/attendance.json`
4. Renders an interactive web dashboard with annual, monthly, weekly, and individual views
5. Sends automated Slack reports (last week + current month + current year) every Monday 9:30 AM IST
6. Deploys the dashboard automatically to GitHub Pages on every data push

## Status codes

| Code | Meaning | Example trigger |
|---|---|---|
| `office` | At office or official travel | "At office", "WF-Sec25A", "at customer site" |
| `wfh` | Working from home | "WFH today", "working remotely" |
| `sick` | Sick leave — not working | "Sick leave", "not feeling well, taking day off" |
| `leave` | Planned PTO / personal leave | "On leave", "day off", "PTO" |
| `no_info` | No status posted that day | *(no message in channel)* |

> **Important:** `no_info` is never treated as absent. It means data is unavailable.

## Running locally

```bash
# Clone the repo
git clone https://github.com/anusharmadobe/team-attendance.git
cd team-attendance

# Serve the source dashboard (reads data/attendance.json directly)
python3 -m http.server 8899
# Open http://localhost:8899/dashboard.html

# Or build the production version and serve that
python3 build.py
python3 -m http.server 8899 --directory dist
# Open http://localhost:8899
```

## Generating reports manually

```bash
# Last week (Mon–Fri of previous week)
python3 generate_report.py last_week

# Current month to date
python3 generate_report.py month

# Current year to date
python3 generate_report.py year

# Previous month (full)
python3 generate_report.py last_month

# Previous full year
python3 generate_report.py last_year

# Custom date range
python3 generate_report.py 2026-04-01 2026-04-30
```

## Office attendance target

**60% of reported days** = 3 days per week mandate.  
Percentages are calculated against *reported* days only (days with a known status), never against total working days. `no_info` days are excluded from the denominator.

---

## Key design decisions

- **No assumptions:** `no_info` ≠ absent. Missing data is surfaced as a confidence gap, not counted against anyone.
- **Correction priority:** If someone posts multiple statuses in a day, higher-priority wins: `office > wfh > sick > leave > no_info`.
- **Official travel = office:** Visits to customer sites, workshops, other Adobe buildings count as office days.
- **Family illness ≠ sick:** WFH due to a family member being ill is classified as WFH, not sick.
- **Single-file build:** `build.py` inlines the JSON data directly into the HTML, avoiding CORS issues on static hosts.
